# Changelog

## 0.3.0

- Debug reports for users who can't run the CLI: `mist.report()` returns a report with the plugin, mist-api, Evi and Discord versions, the plugin's status, and its recent page and native logs and calls. Every recorded value shows as its type and size only. `mist.copyReport()` copies it and toasts the result, for a button in `settingsPanel`, and `mist.reportCommand()` is a slash command for `ctx.command` that copies it, or shows it when copying fails.
- A `stores` getter that reads a missing store during the synchronous part of a plugin's `start` is a warning: `mist.log.warn` prints it once, naming the store and `subscribe(["StoreName"], …)` or `useStore("StoreName", …)` as the fix, and `HandleState.warnings` lists it for the run. Evi starts plugins before Discord makes many stores, so such a read gets `undefined` and code built on it does nothing.
- `createMist` takes `provides`, the bus protocols a plugin offers with their versions, and `needs`, the protocols it speaks with other plugins. The handle advertises `provides`. A needed plugin that is installed and turned on, but provides another version or says nothing (copies of 0.2.1 and earlier), is a warning in `HandleState.warnings`, a log line, and one toast that tells the user which plugin to update.
- Settings migrations: `mist.define({ migrate: [{ to, run }] })` runs each step whose `to` is above the stored settings version, in order, before `start`, and stores the version with the plugin's settings under `__mist_settingsVersion` (`SETTINGS_VERSION`). Evi keeps stored values of keys a schema no longer declares, so a step can read a renamed setting's old value. A step that throws is logged and listed in `HandleState.warnings`, and the plugin still starts; it runs again at the next start.
- `mist.storage`: a key-value store in the page's IndexedDB with `get`, `set`, `update`, `del`, `keys` and `clear`, in a database of the plugin's own, `mist-api:<id>`. Values are stored as JSON. `update` reads and writes in one transaction, so updates at the same time don't lose each other's writes. Its function must be synchronous: one that returns a promise makes `update` reject with a `TypeError` and stores nothing. `mist.storage.account(userId)` is a separate store for one Discord account, since Discord switches accounts without reloading the page. Every error rejects the call, and a page without IndexedDB rejects with an error that says so.
- `mist.signal` is an `AbortSignal` that aborts when the run stops, a new one for each start and an aborted one between runs, for `sleep`, `fetchWithTimeout` and `fetch`. `mist.toast` is `ctx.toast` while the plugin runs and does nothing between runs, where `mist.ctx.toast` throws.
- `mist.define` checks `$self` names in the patches' string replacements. A `$self.name` or `$self?.name?.(…)` that the definition has no function for is a warning, logged once and listed in `HandleState.warnings` for each run, with the nearest function name when there is one. A typo used to show up as a `TypeError` inside Discord's code. Function replacements aren't checked.
- `HandleState` has `provides` and `warnings`. Warnings aren't registry concerns, so they don't stop `mist call`, and `mist status` prints each one on a `warning` line under its plugin.
- `@aurologic/mist-api/discord`, a new subpath for the page side. See `docs/discord.md`.
  - `accounts.list()` reads Discord's saved accounts whatever shape `MultiAccountStore` gives, and never copies their tokens. `accounts.current()` stays right during a switch, while `UserStore` is empty, by reading Discord's `MultiAccountSwitchStore`. `accounts.on("switching" | "signedOut" | "connected", listener)` returns its unsubscribe. `accounts.switchTo(id)` calls Discord's own switch, and `whenConnected(signal?)` resolves with the account id once Discord is connected.
  - `discord(mist)` returns `rest` and `messages` for the plugin. It takes only the plugin's own mist object, after `mist.define`, checked against the handle in the page registry (`MistHandle.owns`), and throws a `TypeError` for a string id or another object with the plugin's `id`, so a plugin can't borrow another's permissions by naming it. `rest.get`, `post`, `put`, `patch`, and `del` go through Discord's own API client and throw a `DiscordApiError` with `status`, `code`, and `retryAfter`. `messages(channelId, { before | after, limit })` pages through a channel's messages and waits out a 429. It throws for bad arguments, a `limit` that is negative or not finite, and a missing permission when called, not at the first `next()`.
  - Requests through `discord(mist)` follow the rules Evi applies to the plugin's own `fetch`, which Evi can't apply to Discord's client: `network` must cover `discord.com`, a write to a message or settings endpoint needs `sendMessages` or `changeSettings`, and `messages` needs `readMessages`. A refused request throws a `PluginPermissionError` that names what to declare, before anything is sent. A plugin without `permissions` in its manifest isn't held to anything, as in Evi. An id Evi has no loaded plugin by throws an `UnknownPluginError`.
  - `navigate(path)` uses Discord's router. `avatarUrl(user, size?)` gives an avatar or Discord's default one. `copy(text)` keeps its `DiscordNative.clipboard` and `clipboard.writeText` visible to Evi's store review.
  - `format.clock`, `format.duration`, `format.ago`, and `format.date` write in Discord's language rather than the system's.
  - `chat.insertText(text)` types into the open message box, and `chat.localMessage(text, channelId?)` shows an "Only you can see this" message outside a slash command.
- `mist flux [types...]` prints Flux actions as Discord dispatches them: the named types, or every action. It stops after `-n` actions, or with `-f` at Ctrl+C, and then removes its listener from the page. A listener the CLI leaves behind, as when it is killed, removes itself 15 seconds after the CLI last read it. Payloads are masked like recorded values, so the tokens in actions such as `CONNECTION_OPEN` show as `"[secret]"`, and cut to short display bounds. `--full` cuts them at the bounds of recorded values. Between the CLI's reads, the page keeps the actions on `globalThis`, where any plugin can read them, message text included; `docs/security.md` says so.
- `mist store <name>` lists a Flux store's methods and its `getState` keys. `mist store <name> <method> [args]` calls a method and prints the result, masked and cut like a `flux` payload. It calls only methods named as reads (`get`, `is`, `has`, `find`, `can`, `should`, `are`, `supports`), and not `getOr...` or `getAnd...` ones, which change state. A method named like a secret, such as `getToken`, has its result masked.
- `mist inspect <selector>` prints an element and its ancestors up to `--depth`: size and position, the computed layout values that aren't the initial ones (`display`, `flex`, `justify-content`, `gap`, margins, padding, `overflow`, `white-space`, and more), the first children, and each CSS rule from `document.styleSheets` that matches and sets layout, with its declarations and source. `--all` prints every match.
- `mist errors [id] [-f]` prints console errors, uncaught exceptions, and the page's error log entries, with the ones from before it ran. It attributes each to a plugin by Evi's logger and its messages for errors it catches (hooks, start, reload, a patched module that threw), or by a stack frame in a plugin's code or in a module it patched. A watch build's frames are printed at their place in the plugin's source files, from the inline source map of the build each frame ran in; a frame from an error's stack text is left unmapped when a hot reload left several builds at its URL. Object arguments are masked like recorded values, and every printed URL loses its query string and fragment, with a webhook URL's token shown as `[secret]`. It turns on CDP's debugger only after telling it to skip every pause, so Discord's page never stops at a breakpoint, and resumes any pause that comes anyway.
- `mist perf` prints `Evi.perf.snapshot()`, each plugin's time and slowest sites, and lists the applied patches whose `$self` functions haven't run.
- `mist dev <id>` follows a plugin's hot reloads through `Evi.plugins.subscribe` and prints each once it settles: the new version, running or its start error, a reload Discord needs, and the patch health.
- `mist module <id|text> [--diff]` prints a webpack module's source as Evi's patches left it, or each change against Discord's original with the plugins it is likely from. Patch matches are measured on the original as Evi normalises it, so a method shorthand factory names the right patch. It turns on the debugger as `mist errors` does.
- `mist react <selector>` prints the React components that render an element, nearest first, with masked props, and marks the ones Evi hooked. A password input's `value` and `defaultValue` are masked, as are those of an input whose `autoComplete` mentions `password` or `one-time-code`.
- `mist manifest fix [dir]` checks a `manifest.json` without Discord: the translations Evi's store asks for, with an empty list of notes counted as missing, and the 16 KB limit Evi's plugin CLI puts on the built manifest. With `--write`, it adds each missing translation as a copy of the English text, and drops other languages' notes for the oldest versions, in semver order, until the manifest fits. When even dropping all of them wouldn't fit, it drops and writes nothing and says how many bytes over it is.
- `mist leaks <id> --yes` turns a running dev build off and on `--cycles` times and prints the counts that grew with every cycle: elements, styles, Flux subscribers and interceptors, and event listeners. It refuses any other plugin, and a plugin with a native side or Chromium switches, which Evi asks about in a dialog each time it is turned on. It leaves the plugin on, also when turning it off fails, and Ctrl+C stops it after it turns the plugin on again.
- `@aurologic/mist-api/testing` has test doubles for a plugin's unit tests, for any test runner: `fakeContext` (a plugin context typed as Evi's `PluginContext`, recording logs, styles, toasts, Flux subscriptions, and disposers), `fakeStore` (a Flux store with listeners and `change()`), `fakeDispatcher`, and `fakeEvi` (a module object for a module mock of `@evi/api`, with `findStore`, `getStore`, `waitFor`, `filters.byStoreName`, the dispatcher, React, and `addStore` to make a store arrive late). See `docs/testing.md`.
- Typed errors across IPC. A native method made with `defineNative` can `throw new NativeError(code, data?)`, and the page's `mist.native` call rejects with a `MistNativeError` with the same `code`, `message`, and a structured clone of `data`. An `HttpError` keeps its `status`, and other errors keep their `name` and `message` without Electron's `Error invoking remote method` prefix.
- Cancelling a native call: `mist.native.method.with({ signal })(...args)` rejects at once when the signal aborts and aborts the method's `this.signal` on the native side. `this.signal` also aborts for every call in flight when the native side stops.
- Native requests: `nativeRequests<T>()` lets native code ask the page and wait (`request(name, payload, { timeoutMs, signal })`), and the page answers with `mist.requests.handle(name, handler)`, typed from the native module. Requests time out, fail with a code when the page has no handler or its handler throws, and are rejected when the native side stops. They ride a second long-polled channel, so Evi needs no change.
- The page asks a native side's new hidden `__mist_protocol` once per run and adds a call mark only when it answers. Native sides made with 0.2.1 or earlier, or without `defineNative`, get calls exactly as before, and pages made with 0.2.1 or earlier work with this `defineNative` as before. See "How a call crosses IPC" in `docs/native.md`.
- A native toolkit in `@aurologic/mist-api/native`, see `docs/toolkit.md`:
  - `discordWindow()` finds Discord's main window from `global.mainWindowId`, or else the first window showing Discord's app, never the splash screen, overlay or a popout.
  - `lifetime(ctx)` is a scope whose `spawn`, `interval`, `timeout`, `window` and `signal` are cleaned up when the native side stops or hot reloads. Child processes get `SIGTERM`, then `SIGKILL` after `killAfterMs`. Evi doesn't stop native sides when Discord quits, so children also get `SIGTERM` then.
  - `run(file, args, { timeout, signal, input, maxBytes })` runs a program without a shell and collects its output. `which(name)` finds a program on `PATH`, with `PATHEXT` on Windows.
  - `dataFolder(ctx)` is the plugin's own folder, `<ctx.dataDir>/plugin-data/<id>`. `jsonFile(ctx, name, { initial, parse, maxBytes, debounceMs })` keeps a JSON file there with `get`, `set` and `flush`: debounced, atomic writes (temporary file and rename), flushed on stop and when Discord quits, and a file that can't be parsed kept as `.bad`. A file that exists but can't be read (locked, no access, over `maxBytes`) is left alone, and `get` and `set` throw a `NativeError` `file-unreadable` until it can be read, so no write replaces it. Every `jsonFile` of one name in a run is the same object, and `secrets` and `pathGrants` share their files the same way, so two of them don't overwrite each other's writes.
  - `secrets(ctx)` keeps strings encrypted with Electron's `safeStorage` in the plugin's folder, with `encrypted: false` when Electron falls back to Chromium's built-in key on Linux. Other plugins' native code shares the process and can read them; the docs say so.
  - `pathGrants(ctx)` shows a file or folder dialog and gives the page an opaque handle; only native code turns it into a path with `resolveGrant`, and a folder's handle reaches only paths inside it.
- Inside a `defineNative` method, `this` is the module plus the call's `signal`; state a method stores on `this` still lands on the module. In `start` and `stop`, `this.signal` is the run's signal, which aborts once `stop` returns.
- `@aurologic/mist-api/ui`, a new subpath for a plugin's UI inside Discord's. See `docs/ui.md`.
  - `Boundary` and `boundary(Component, { fallback, name, mist })` catch render errors in a plugin's UI and show a one-line notice with Retry, a node, or a function of the error and a retry, in place of the UI. Each distinct error is logged once, through the plugin's `mist.log` or the console.
  - `state(initial)` is an observable value with `get`, `set` and `update`, and a `ChangeSource`, so `useStore` and `subscribe` take it. `useValue(state)` is its hook.
  - `host(name)` is a mount point for patches that stays the same component across hot reloads and copies of mist-api. It renders what the running plugin `set`, and nothing while the plugin is stopped.
  - `chatBar.add`, `popover.add` and `accessories.add` add buttons to the chat bar before the send button, buttons to the hover bar of each message, and UI under each message. `ChatBarButton` looks like Discord's own chat bar buttons, and a hover bar entry gets Discord's hover bar button to render.
  - `messages.beforeSend` and `messages.beforeEdit` run listeners, which may be async, before a message from the chat box is sent and before an edit is saved. A listener can change the content or return `{ cancel: true }` to keep the text in the box. The message waits at most 5 seconds for each listener; one that takes longer is logged once to its plugin, and the message goes on with the content it had before that listener.
  - The registries take only the plugin's own mist object, after `mist.define`, checked as `discord(mist)` checks it. `popover.add`, `accessories.add`, `messages.beforeSend`, and `messages.beforeEdit` see message content, so they need `readMessages` in a manifest that declares `permissions`, as Evi's guard asks of a hook on sending, and throw a `PluginPermissionError` otherwise; `@aurologic/mist-api/ui` exports it and `UnknownPluginError`. Like Evi's guard, this isn't a sandbox; `docs/ui.md` and `docs/security.md` say what it does and doesn't stop.
  - Each registry has `patches` for the plugin's `patches`. Plugins that bundle different copies share each registry through a versioned `Symbol.for` key, the patched code calls it once however many plugins carry the patches, each entry renders in a `Boundary`, and each entry goes when its plugin stops.

## 0.2.1

- `subscribe` and `useStore` in `@aurologic/mist-api/stores` take a Flux store's name, such as `"PresenceStore"`. A store Discord hasn't made yet is listened to once it has, and the listener is called then. Evi starts plugins before Discord makes many of its stores, so `subscribe([stores.presence], redraw)` in `start` could listen to nothing after a cold start; `subscribe(["PresenceStore"], redraw)` can't. The docs' own example showed the first form and now shows the second.

## 0.2.0

The first release of mist-api, a TypeScript library for Evi plugins.

- `@aurologic/mist-api`: `createMist(id)` is the page side of a plugin. It holds the plugin's context (`mist.ctx`, `mist.running`), types native calls from the plugin's `native.ts` (`mist.native`), and logs through `mist.log`. `mist.expose` publishes values for the CLI, and `mist.safe` wraps a patch callback so it never throws. `onDemand(patch)` marks a source patch whose code Discord downloads later, so the CLI shows it as waiting rather than broken. `MIST_VERSION` is the version of the copy.
- `@aurologic/mist-api/native`: `defineNative(methods)` is the main-process side. It records calls and logs for the CLI, and `debugAllowed()` says whether Discord's main process has a debugging port.
- Events from the native side to the page: `nativeEvents()` makes an ordered, capped event log, and `mist.events.subscribe` reads it, typed from the native module. A page that connects or reconnects runs `onConnect` and gets only the events that `replay` accepts from before. A restart of the native side is detected by a boot id. `stop` answers every waiting poll. See `docs/events.md`.
- `@aurologic/mist-api/stores`: typed Discord Flux stores (`stores`), `currentUserId`, `isStreamerMode`, `subscribe`, and the React hook `useStore`.
- `@aurologic/mist-api/util`: `isRecord`, `sleep`, `fetchWithTimeout`, `fetchJson`, `HttpError`, and the types of Discord's `DiscordNative` bridge.
- `@aurologic/mist-api/bus`: versioned channels and slots that plugins use to talk to each other, shared on `globalThis`.
- The `mist` CLI reads each plugin's logs, native calls, native logs, and exposed values over the Chrome DevTools Protocol. It can also call native methods, list patches, evaluate code, and restart Discord with a debugging port. Run it with `npx -p @aurologic/mist-api mist`.
- Recorded values mask fields named like secrets (`token`, `password`, `cookie`, and similar), plus the names a plugin gives in `secrets` and the arguments it names in `secretArgs`. `reveal` shows a name that a built-in name would mask, and `quiet` counts a method's calls without keeping them.
- Calling native methods, and reading the native side's records whole, work only when Discord's main process was started with a debugging port.
- The page registry keeps a running plugin's handle in place: page code can't replace it. A handle replaced while its plugin was stopped is taken back at the plugin's next start. `mist status` shows each registry concern, and `mist call` sends no arguments to a handle with one. `docs/security.md` has the security model and what page code can still do.
- Copies of different versions, bundled into different plugins, share one debug registry and one bus through versioned `Symbol.for` keys.
