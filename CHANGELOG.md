# Changelog

## 0.5.0

- `@aurologic/mist-api`, the page side:
  - `mist.settings`, `mist.data`, and `mist.flux` work between runs. `mist.settings` has `get`, `set`, `all`, `onChange`, and a `use(key)` hook. It is a `ChangeSource`, and between runs it reads the schema's defaults.
  - `mist.data(key, initial, { parse })` is a typed value kept in Evi's settings, with `get`, `set`, `update`, `onChange`, and `use()`. It is a `ChangeSource`: `useStore`, `subscribe`, and `useValue` take it. `get` returns a fresh JSON copy (or the cached `parse` result), and `set` stores a JSON copy, throwing a `TypeError` that names the key for a value JSON can't hold, such as a `BigInt`. `parse` checks a fresh copy of each stored value when it is read, and a `parse` that throws gives the initial value.
  - `mist.flux.on<A>(types, handler)` subscribes for the run, and `mist.flux.next<A>(types, { where, timeout, signal })` waits for one action.
  - A `mist.settings.set`, `mist.data` write, or `mist.flux.on` made while the plugin is stopped does nothing, and mist logs it once at debug level: `mist.flux.on: ignored while <id> is stopped`.
  - `createMist` registers the plugin's handle at once. `discord(mist)` and the UI registries work at module level and no longer need `mist.define` first. `mist.define` returns a `DefinedPlugin<S>`, whose `start` is always there.
  - A permission check finds the plugin first in a private map of the copy of mist-api that made its `mist`, and then in the page registry. `docs/security.md` says what that does and doesn't prove.
- `@aurologic/mist-api/discord`:
  - `navigate.channel(channelId, { guildId, messageId })` finds the server itself. It throws when the channel isn't in `ChannelStore` and no `guildId` is given; pass `guildId: null` for a DM.
  - `snowflake` has `is`, `assert`, `time`, `at`, and `compare`. `is` and `assert` accept ids up to 2⁶⁴ − 1. `assert` throws a `TypeError`, and `at` a `RangeError`.
  - `displayName(user, { guildId, fallback })` reads the server nickname, then the friend nickname, then the global name, then the user name.
  - `api.rest` requests that read messages now need `readMessages`, as `api.messages` did: `GET` on `/channels/<id>/messages`, `/pins`, `/threads/search`, a server's message search, and `/users/@me/mentions`, and `POST` on `/channels/<id>/post-data`. A `GET` or `POST` path with a control character, a `;`, or an escape that doesn't decode counts as a message read. `api.rest` and `navigate` reject `.` and `..` path segments.
  - `api.messages` waits out a 429 for its `retry_after`, at most the timer limit.
  - `settings.update<G>` is typed by its group, and a save that times out resolves `"failed"` without reloading Discord's settings.
  - `accounts` prints an error from a listener, a scope, or Discord's switch with `console.error` instead of `reportError`. A scope's signal aborts with a `DOMException` named `AbortError`.
- `@aurologic/mist-api/stores`:
  - `store(name)`, `whenStore(name, signal | { signal, timeout })`, and `lookup(filter)`. `whenStore` rejects with a `TimeoutError` when its timeout passes.
  - Typed getters for `messages`, `readStates`, `voiceStates`, `guildMembers`, `relationships` (with `getNickname`), and `permissions`. `stores.messages` needs `readMessages`.
  - `subscribe` removes the listeners it already added when a later source throws. `useStore` takes a list of sources that changes between renders.
- `@aurologic/mist-api/util`:
  - `isSnowflake`, `debounce(fn, ms | "frame", { signal, flushOnAbort })` with `flush` and `cancel`, `withTimeout(work, ms, signal | { signal })`, and `until(check, { timeout, every, signal })`, which needs a `timeout` or a `signal`. A `"frame"` debounce in a hidden tab runs after 16 ms.
  - `fetchWithTimeout` and `fetchJson` take a `fetch` to send through.
  - Delays and timeouts are checked against the timer limit, 2147483647 ms. A value that isn't a number is a `TypeError`. A number that is negative, not whole, or over the limit is a `RangeError`.
- `@aurologic/mist-api/ui`:
  - `Switch`, and `TextInput` with a `label` above it and a `description` that screen readers read with it.
  - A `state` has `use()`, a hook, and `onChange(listener)`.
  - Each `beforeSend` and `beforeEdit` listener gets a copy of the draft. The changes of a listener that throws or times out are dropped instead of half kept.
  - A hot reload gives each entry a fresh error boundary, and UI that threw renders again. `chatBar` and `popover` render nothing on a crash by default. The error log stops after 50 distinct errors, with a notice.
- `@aurologic/mist-api/native`:
  - `writeAtomic(path, content)` and `writeAtomicSync(path, content)` write a string or a `Uint8Array` through a temporary file and a rename.
  - `events.push` and `request` throw `NativeError("unclonable")` for data IPC can't copy.
  - On Windows, `run` and `lifetime().spawn` throw `NativeError("needs-shell")` for a `.cmd` or `.bat` file, where Node failed with `EINVAL`.
  - `lifetime().signal` aborts with a `DOMException` named `AbortError`. A throwing interval, timeout, or cleanup is logged instead of reaching main as an uncaught exception. `run` no longer waits for a grandchild that keeps the pipes open.
  - `which` reads `Path` and `PATHEXT` in any case.
  - A `jsonFile` that can't be parsed and can't be moved to `.bad` counts as unreadable, and no write replaces it.
  - `privateSession` uses the partition `persist:mist:<pluginId>:<name>`, which two plugins can't share. The old `persist:<pluginId>-<name>` could (`a` with `b-c`, `a-b` with `c`).
    - The first call moves the old partition's cookies one at a time, and users stay signed in. A cookie that fails is logged and skipped. A `mist-session-<name>.migrated` file in the plugin's data folder marks the move as done.
    - When another installed plugin could have made the same old partition name, the cookies stay where they are, a warning says to sign in again, and the marker is written.
    - `loginWindow` waits for the move before it loads. `clear()` clears the old partition too.
- `@aurologic/mist-api/bus`:
  - The `Channel<T>` type is now `BusChannel<T>`.
  - A bad name or version throws a `TypeError` or `RangeError`, and a key made by an incompatible copy a `TypeError`. Each message starts with `channel` or `slot`.
  - The bus prints a listener's error without the value.
- Native events and requests: the page asks the native side's protocol again after a failed ask, with a growing delay. `mist.events.subscribe` waits longer after each failed poll, from `retryMs` up to 30 seconds. A subscription to a plugin without an event channel logs once and stops.
- The `mist` CLI:
  - `mist --version` (`-v`) prints the CLI's version.
  - `mist` refuses an option it doesn't know instead of reading it as an argument, and `--` ends the options. It checks required arguments and numbers before it connects, and `--port` takes 1 to 65535.
  - Expected errors (`CliError`) print their message alone. Anything else prints its stack. With `--json`, an error prints as `{"error": "..."}` on stdout.
  - `mist status` prints a registry concern on a `concern:` line, where it printed `WARNING:`. `mist calls` marks a call that threw `failed`, where it printed `FAILED`.
  - `mist restart` on Windows fails with a message when `LOCALAPPDATA` isn't set.
  - `mist logs -f` says when more than `-n` lines came between two reads. `mist react --json` names its reason `problem`, not `error`. `mist manifest fix` says to add a `name` when the manifest has none.
- `@aurologic/mist-api/testing`:
  - `fakeEvi()`'s module has `filters.byProps` and `filters.byCode`. `fakeEvi()` has `plugins`, `setPlugin(id, info?)`, `removePlugin(id)`, and `installGlobal()`, which sets `globalThis.Evi` to the fake's plugin list and settings for `discord(mist)` and the UI registries, and returns a function that restores it.
  - `fakeElectron()`'s `BrowserWindow` is a class, and `instanceof` works.
- `check-pack` runs with Bun.

## 0.4.0

- `@aurologic/mist-api/util` has the retry and streaming pieces plugins write by hand. `shared(fn)` keeps one run of an async function in flight and gives later callers the same promise, and `sharedByKey(fn)` does so per key. `backoff({ baseMs, maxMs, factor, jitter, random })` gives growing retry delays with jitter. `keepConnected(connect, { signal, backoff, onError, sleep })` runs a connection again and again until the signal aborts, waits the backoff between runs, resets it once `connected()` is called, and never spins on a connection that ends at once. `sseEvents(source, signal?)` reads server-sent events from a `Response` or a stream and cancels it when the loop stops or the signal aborts, and `parseSse(buffer)` is its incremental parser. `ttlCache({ ttlMs, max, now })` is a map with expiry and a least-recently-used cap. `limit(n)` runs at most `n` async functions at once, the rest in arrival order.
- `@aurologic/mist-api/native` has argument guards and a private login. `check.text`, `id`, `int`, `bool`, `oneOf`, `https`, `list` and `record` check the page's arguments and throw `NativeError("bad-argument", { name, expected })`. `check.https` takes a host allowlist, where `*.example.com` covers subdomains. `privateSession(ctx, name)` is an Electron session apart from Discord's, on `persist:<pluginId>-<name>`, that denies every permission request, with `fetch`, `json`, `cookie`, `hasCookie`, `clear` and `flush`, and an optional browser user agent. `loginWindow(session, { url, done })` opens a sandboxed sign-in window centred over Discord's, https only, with popups denied, resolves `true` when `done` first answers true and `false` when the user closes it or the signal aborts, and always destroys the window and flushes cookies first. A second call for the same session focuses the open window. `openExternal(url, { hosts })` opens an https link in the user's browser.
- `@aurologic/mist-api/testing` has `fakeElectron()`, a module object for a module mock of `electron` in native tests: windows with `loadURL`, `closed` and the window-open handler recorded, `session.fromPartition` with a programmable `fetch`, a cookie jar and recorded permission handlers, `shell.openExternal`, dialogs with set answers, `safeStorage`, and `app`. It imports neither `electron` nor a test runner. `fakeEvi()`'s module has an empty `Components`.
- `@aurologic/mist-api/discord` does more of what account and status plugins rebuild. `accounts.switchTo` resolves with `"switched"`, `"already"`, `"needsLogin"` (no saved login for that account) or `"failed"`, where it resolved with nothing before. `accounts.openLogin()` opens Discord's add-an-account login. `accounts.scope(run, { settleMs })` runs `run(accountId, signal)` for each connected account, aborts the signal and runs its cleanup when the account switches or signs out, and reports what `run` throws instead of throwing into Discord's dispatch. `discord(mist).settings.update(proto, group, change)` writes Discord's settings through Discord's updater and waits for the save, and `discord(mist).status.get()` and `.set(status | null)` read and write the custom status on it. Both are held to the manifest's `changeSettings`. `format.messageLink` and `parseMessageLink` write and read message links on discord.com, its ptb. and canary. hosts, and discordapp.com.
- `@aurologic/mist-api/ui` has settings-panel pieces that look like Discord's: `Button` (primary, secondary, danger or link, with a size and a busy state), `Tip`, `Card`, `Row` and `Callout`. `Button` and `Tip` use Evi's `Components` and fall back to mist-api's versions when Discord's are missing. One stylesheet with Discord's CSS variables, which follow both themes, is added once and removed when the last piece unmounts.
- `mist manifest bump [dir] <version | patch | minor | major> --note "..."` sets the next version and adds its changelog entry, in English and in each language Evi ships, from `--note-<lang>` or as a copy of the English notes. It refuses a version that isn't higher, fits the 16 KB as `manifest fix --write` does, and writes only with `--write`. It and `manifest fix --write` now keep the file's line endings, indentation, key order and final newline.
- `mist restart --wait <id> [--timeout <s>]` waits after the restart until the plugin's page side runs, as `mist status` sees it, prints one line, and exits with code 1 when it doesn't run within the timeout (60 seconds by default).

## 0.3.1

- `@aurologic/mist-api/native` loads next to a test's mock of `electron` that has only some of Electron's exports. 0.3.0 imported `app`, `BrowserWindow`, `dialog` and `safeStorage` by name. A plugin whose native tests mocked `electron` with only `net`, say, failed to load mist at all. mist now reads them from Electron when a toolkit function runs, and the quit hook does nothing where there is no `app`.

## 0.3.0

- Debug reports for users who can't run the CLI: `mist.report()` returns a report with the plugin, mist-api, Evi and Discord versions, the plugin's status, and its recent page and native logs and calls. Every recorded value shows as its type and size only. `mist.copyReport()` copies it and toasts the result, for a button in `settingsPanel`, and `mist.reportCommand()` is a slash command for `ctx.command` that copies it, or shows it when copying fails.
- A `stores` getter that reads a missing store during the synchronous part of a plugin's `start` is a warning: `mist.log.warn` prints it once, naming the store and `subscribe(["StoreName"], …)` or `useStore("StoreName", …)` as the fix, and `HandleState.warnings` lists it for the run. Evi starts plugins before Discord makes many stores, and such a read gets `undefined` and code built on it does nothing.
- `createMist` takes `provides`, the bus protocols a plugin offers with their versions, and `needs`, the protocols it speaks with other plugins. The handle advertises `provides`. A needed plugin that is installed and turned on, but provides another version or says nothing (copies of 0.2.1 and earlier), is a warning in `HandleState.warnings`, a log line, and one toast that tells the user which plugin to update.
- Settings migrations: `mist.define({ migrate: [{ to, run }] })` runs each step whose `to` is above the stored settings version, in order, before `start`, and stores the version with the plugin's settings under `__mist_settingsVersion` (`SETTINGS_VERSION`). Evi keeps stored values of keys a schema no longer declares: a step can read a renamed setting's old value. A step that throws is logged and listed in `HandleState.warnings`, and the plugin still starts; it runs again at the next start.
- `mist.storage`: a key-value store in the page's IndexedDB with `get`, `set`, `update`, `del`, `keys` and `clear`, in a separate database for each plugin, `mist-api:<id>`. Values are stored as JSON. `update` reads and writes in one transaction: updates at the same time don't lose each other's writes. Its function must be synchronous: one that returns a promise makes `update` reject with a `TypeError` and stores nothing. `mist.storage.account(userId)` is a separate store for one Discord account, since Discord switches accounts without reloading the page. Every error rejects the call, and a page without IndexedDB rejects with an error that says so.
- `mist.signal` is an `AbortSignal` that aborts when the run stops, a new one for each start and an aborted one between runs, for `sleep`, `fetchWithTimeout` and `fetch`. `mist.toast` is `ctx.toast` while the plugin runs and does nothing between runs, where `mist.ctx.toast` throws.
- `mist.define` checks `$self` names in the patches' string replacements. A `$self.name` or `$self?.name?.(…)` that the definition has no function for is a warning, logged once and listed in `HandleState.warnings` for each run, with the nearest function name when there is one. A typo used to show up as a `TypeError` inside Discord's code. Function replacements aren't checked.
- `HandleState` has `provides` and `warnings`. Warnings aren't registry concerns and don't stop `mist call`. `mist status` prints each one on a `warning` line under its plugin.
- `@aurologic/mist-api/discord`, a new subpath for the page side. See `docs/discord.md`.
  - `accounts.list()` reads Discord's saved accounts whatever shape `MultiAccountStore` gives, and never copies their tokens. `accounts.current()` stays right during a switch, while `UserStore` is empty, by reading Discord's `MultiAccountSwitchStore`. `accounts.on("switching" | "signedOut" | "connected", listener)` returns its unsubscribe. `accounts.switchTo(id)` calls Discord's switch, and `whenConnected(signal?)` resolves with the account id once Discord is connected.
  - `discord(mist)` returns `rest` and `messages` for the plugin. It takes only the plugin's mist object, after `mist.define`, checked against the handle in the page registry (`MistHandle.owns`), and throws a `TypeError` for a string id or another object with the plugin's `id`. A plugin can't borrow another's permissions by naming it. `rest.get`, `post`, `put`, `patch`, and `del` go through Discord's API client and throw a `DiscordApiError` with `status`, `code`, and `retryAfter`. `messages(channelId, { before | after, limit })` pages through a channel's messages and waits out a 429. It throws for bad arguments, a `limit` that is negative or not finite, and a missing permission when called, not at the first `next()`.
  - Requests through `discord(mist)` follow the rules Evi applies to the plugin's `fetch`, which Evi can't apply to Discord's client: `network` must cover `discord.com`, a write to a message or settings endpoint needs `sendMessages` or `changeSettings`, and `messages` needs `readMessages`. A refused request throws a `PluginPermissionError` that names what to declare, before anything is sent. A plugin without `permissions` in its manifest isn't held to anything, as in Evi. An id that matches no plugin Evi has loaded throws an `UnknownPluginError`.
  - `navigate(path)` uses Discord's router. `avatarUrl(user, size?)` gives an avatar or Discord's default one. `copy(text)` keeps its `DiscordNative.clipboard` and `clipboard.writeText` visible to Evi's store review.
  - `format.clock`, `format.duration`, `format.ago`, and `format.date` write in Discord's language rather than the system's.
  - `chat.insertText(text)` types into the open message box, and `chat.localMessage(text, channelId?)` shows an "Only you can see this" message outside a slash command.
- `mist flux [types...]` prints Flux actions as Discord dispatches them: the named types, or every action. It stops after `-n` actions, or with `-f` at Ctrl+C, and then removes its listener from the page. A listener the CLI leaves behind, as when it is killed, removes itself 15 seconds after the CLI last read it. Payloads are masked like recorded values, with the tokens in actions such as `CONNECTION_OPEN` show as `"[secret]"`, and cut to short display bounds. `--full` cuts them at the bounds of recorded values. Between the CLI's reads, the page keeps the actions on `globalThis`, where any plugin can read them, message text included; `docs/security.md` says so.
- `mist store <name>` lists a Flux store's methods and its `getState` keys. `mist store <name> <method> [args]` calls a method and prints the result, masked and cut like a `flux` payload. It calls only methods named as reads (`get`, `is`, `has`, `find`, `can`, `should`, `are`, `supports`), and not `getOr...` or `getAnd...` ones, which change state. A method named like a secret, such as `getToken`, has its result masked.
- `mist inspect <selector>` prints an element and its ancestors up to `--depth`: size and position, the computed layout values that aren't the initial ones (`display`, `flex`, `justify-content`, `gap`, margins, padding, `overflow`, `white-space`, and more), the first children, and each CSS rule from `document.styleSheets` that matches and sets layout, with its declarations and source. `--all` prints every match.
- `mist errors [id] [-f]` prints console errors, uncaught exceptions, and the page's error log entries, with the ones from before it ran. It attributes each to a plugin by Evi's logger and its messages for errors it catches (hooks, start, reload, a patched module that threw), or by a stack frame in a plugin's code or in a module it patched. A watch build's frames are printed at their place in the plugin's source files, from the inline source map of the build each frame ran in; a frame from an error's stack text is left unmapped when a hot reload left several builds at its URL. Object arguments are masked like recorded values, and every printed URL loses its query string and fragment, with a webhook URL's token shown as `[secret]`. It turns on CDP's debugger only after telling it to skip every pause: Discord's page never stops at a breakpoint, and resumes any pause that comes anyway.
- `mist perf` prints `Evi.perf.snapshot()`, each plugin's time and slowest sites, and lists the applied patches whose `$self` functions haven't run.
- `mist dev <id>` follows a plugin's hot reloads through `Evi.plugins.subscribe` and prints each once it settles: the new version, running or its start error, a reload Discord needs, and the patch health.
- `mist module <id|text> [--diff]` prints a webpack module's source as Evi's patches left it, or each change against Discord's original with the plugins it is likely from. Patch matches are measured on the original as Evi normalises it, and a method shorthand factory names the right patch. It turns on the debugger as `mist errors` does.
- `mist react <selector>` prints the React components that render an element, nearest first, with masked props, and marks the ones Evi hooked. A password input's `value` and `defaultValue` are masked, as are those of an input whose `autoComplete` mentions `password` or `one-time-code`.
- `mist manifest fix [dir]` checks a `manifest.json` without Discord: the translations Evi's store asks for, with an empty list of notes counted as missing, and the 16 KB limit Evi's plugin CLI puts on the built manifest. With `--write`, it adds each missing translation as a copy of the English text, and drops other languages' notes for the oldest versions, in semver order, until the manifest fits. When even dropping all of them wouldn't fit, it drops and writes nothing and says how many bytes over it is.
- `mist leaks <id> --yes` turns a running dev build off and on `--cycles` times and prints the counts that grew with every cycle: elements, styles, Flux subscribers and interceptors, and event listeners. It refuses any other plugin, and a plugin with a native side or Chromium switches, which Evi asks about in a dialog each time it is turned on. It leaves the plugin on, also when turning it off fails, and Ctrl+C stops it after it turns the plugin on again.
- `@aurologic/mist-api/testing` has test doubles for a plugin's unit tests, for any test runner: `fakeContext` (a plugin context typed as Evi's `PluginContext`, recording logs, styles, toasts, Flux subscriptions, and disposers), `fakeStore` (a Flux store with listeners and `change()`), `fakeDispatcher`, and `fakeEvi` (a module object for a module mock of `@evi/api`, with `findStore`, `getStore`, `waitFor`, `filters.byStoreName`, `find`, `findAll`, `I18n`, the dispatcher, React, `addStore` to make a store arrive late, and `addExport` for `find` to search). See `docs/testing.md`.
- Typed errors across IPC. A native method made with `defineNative` can `throw new NativeError(code, data?)`, and the page's `mist.native` call rejects with a `MistNativeError` with the same `code`, `message`, and a structured clone of `data`. An `HttpError` keeps its `status`, and other errors keep their `name` and `message` without Electron's `Error invoking remote method` prefix.
- Cancelling a native call: `mist.native.method.with({ signal })(...args)` rejects at once when the signal aborts and aborts the method's `this.signal` on the native side. `this.signal` also aborts for every call in flight when the native side stops.
- Native requests: `nativeRequests<T>()` lets native code ask the page and wait (`request(name, payload, { timeoutMs, signal })`), and the page answers with `mist.requests.handle(name, handler)`, typed from the native module. Requests time out, fail with a code when the page has no handler or its handler throws, and are rejected when the native side stops. They ride a second long-polled channel, and Evi needs no change.
- The page asks a native side's new hidden `__mist_protocol` once per run and adds a call mark only when it answers. Native sides made with 0.2.1 or earlier, or without `defineNative`, get calls exactly as before, and pages made with 0.2.1 or earlier work with this `defineNative` as before. See "How a call crosses IPC" in `docs/native.md`.
- A native toolkit in `@aurologic/mist-api/native`, see `docs/toolkit.md`:
  - `discordWindow()` finds Discord's main window from `global.mainWindowId`, or else the first window showing Discord's app, never the splash screen, overlay or a popout.
  - `lifetime(ctx)` is a scope whose `spawn`, `interval`, `timeout`, `window` and `signal` are cleaned up when the native side stops or hot reloads. Child processes get `SIGTERM`, then `SIGKILL` after `killAfterMs`. Evi doesn't stop native sides when Discord quits, and children also get `SIGTERM` then.
  - `run(file, args, { timeout, signal, input, maxBytes })` runs a program without a shell and collects its output. `which(name)` finds a program on `PATH`, with `PATHEXT` on Windows.
  - `dataFolder(ctx)` is the plugin's folder, `<ctx.dataDir>/plugin-data/<id>`. `jsonFile(ctx, name, { initial, parse, maxBytes, debounceMs })` keeps a JSON file there with `get`, `set` and `flush`: debounced, atomic writes (temporary file and rename), flushed on stop and when Discord quits, and a file that can't be parsed kept as `.bad`. A file that exists but can't be read (locked, no access, over `maxBytes`) is left alone, and `get` and `set` throw a `NativeError` `file-unreadable` until it can be read. No write replaces it. Every `jsonFile` of one name in a run is the same object, and `secrets` and `pathGrants` share their files the same way. Two of them don't overwrite each other's writes.
  - `secrets(ctx)` keeps strings encrypted with Electron's `safeStorage` in the plugin's folder, with `encrypted: false` when Electron falls back to Chromium's built-in key on Linux. Other plugins' native code shares the process and can read them; the docs say so.
  - `pathGrants(ctx)` shows a file or folder dialog and gives the page an opaque handle; only native code turns it into a path with `resolveGrant`, and a folder's handle reaches only paths inside it.
- Inside a `defineNative` method, `this` is the module plus the call's `signal`; state a method stores on `this` still lands on the module. In `start` and `stop`, `this.signal` is the run's signal, which aborts once `stop` returns.
- `@aurologic/mist-api/ui`, a new subpath for a plugin's UI inside Discord's. See `docs/ui.md`.
  - `Boundary` and `boundary(Component, { fallback, name, mist })` catch render errors in a plugin's UI and show a one-line notice with Retry, a node, or a function of the error and a retry, in place of the UI. Each distinct error is logged once, through the plugin's `mist.log` or the console.
  - `state(initial)` is an observable value with `get`, `set` and `update`, and a `ChangeSource` that `useStore` and `subscribe` take. `useValue(state)` is its hook.
  - `host(name)` is a mount point for patches that stays the same component across hot reloads and copies of mist-api. It renders what the running plugin `set`, and nothing while the plugin is stopped.
  - `chatBar.add`, `popover.add` and `accessories.add` add buttons to the chat bar before the send button, buttons to the hover bar of each message, and UI under each message. `ChatBarButton` looks like Discord's chat bar buttons, and a hover bar entry gets Discord's hover bar button to render.
  - `messages.beforeSend` and `messages.beforeEdit` run listeners, which may be async, before a message from the chat box is sent and before an edit is saved. A listener can change the content or return `{ cancel: true }` to keep the text in the box. The message waits at most 5 seconds for each listener; one that takes longer is logged once to its plugin, and the message goes on with the content it had before that listener.
  - The registries take only the plugin's mist object, after `mist.define`, checked as `discord(mist)` checks it. `popover.add`, `accessories.add`, `messages.beforeSend`, and `messages.beforeEdit` see message content and need `readMessages` in a manifest that declares `permissions`, as Evi's guard asks of a hook on sending, and throw a `PluginPermissionError` otherwise; `@aurologic/mist-api/ui` exports it and `UnknownPluginError`. Like Evi's guard, this isn't a sandbox; `docs/ui.md` and `docs/security.md` say what it does and doesn't stop.
  - Each registry has `patches` for the plugin's `patches`. Plugins that bundle different copies share each registry through a versioned `Symbol.for` key, the patched code calls it once however many plugins carry the patches, each entry renders in a `Boundary`, and each entry goes when its plugin stops.

## 0.2.1

- `subscribe` and `useStore` in `@aurologic/mist-api/stores` take a Flux store's name, such as `"PresenceStore"`. A store Discord hasn't made yet is listened to once it has, and the listener is called then. Evi starts plugins before Discord makes many of its stores. `subscribe([stores.presence], redraw)` in `start` could listen to nothing after a cold start; `subscribe(["PresenceStore"], redraw)` can't. The docs' example showed the first form and now shows the second.

## 0.2.0

The first release of mist-api, a TypeScript library for Evi plugins.

- `@aurologic/mist-api`: `createMist(id)` is the page side of a plugin. It holds the plugin's context (`mist.ctx`, `mist.running`), types native calls from the plugin's `native.ts` (`mist.native`), and logs through `mist.log`. `mist.expose` publishes values for the CLI, and `mist.safe` wraps a patch callback so it never throws. `onDemand(patch)` marks a source patch whose code Discord downloads later. The CLI shows it as waiting rather than broken. `MIST_VERSION` is the version of the copy.
- `@aurologic/mist-api/native`: `defineNative(methods)` is the main-process side. It records calls and logs for the CLI, and `debugAllowed()` says whether Discord's main process has a debugging port.
- Events from the native side to the page: `nativeEvents()` makes an ordered, capped event log, and `mist.events.subscribe` reads it, typed from the native module. A page that connects or reconnects runs `onConnect` and gets only the events that `replay` accepts from before. A restart of the native side is detected by a boot id. `stop` answers every waiting poll. See `docs/events.md`.
- `@aurologic/mist-api/stores`: typed Discord Flux stores (`stores`), `currentUserId`, `isStreamerMode`, `subscribe`, and the React hook `useStore`.
- `@aurologic/mist-api/util`: `isRecord`, `sleep`, `fetchWithTimeout`, `fetchJson`, `HttpError`, and the types of Discord's `DiscordNative` bridge.
- `@aurologic/mist-api/bus`: versioned channels and slots that plugins use to talk to each other, shared on `globalThis`.
- The `mist` CLI reads each plugin's logs, native calls, native logs, and exposed values over the Chrome DevTools Protocol. It can also call native methods, list patches, evaluate code, and restart Discord with a debugging port. Run it with `npx -p @aurologic/mist-api mist`.
- Recorded values mask fields named like secrets (`token`, `password`, `cookie`, and similar), plus the names a plugin gives in `secrets` and the arguments it names in `secretArgs`. `reveal` shows a name that a built-in name would mask, and `quiet` counts a method's calls without keeping them.
- Calling native methods, and reading the native side's records whole, work only when Discord's main process was started with a debugging port.
- The page registry keeps a running plugin's handle in place: page code can't replace it. A handle replaced while its plugin was stopped is taken back at the plugin's next start. `mist status` shows each registry concern, and `mist call` sends no arguments to a handle with one. `docs/security.md` has the security model and what page code can still do.
- Copies of different versions, bundled into different plugins, share one debug registry and one bus through versioned `Symbol.for` keys.
